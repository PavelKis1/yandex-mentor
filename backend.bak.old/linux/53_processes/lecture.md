# Лекция: 53 — Процессы и потоки в Linux (ps, top, kill, nice)

## Обзор темы
Каждое запущенное приложение в Linux представляет собой процесс с уникальным идентификатором (PID). Управление процессами, мониторинг потребления ресурсов и отправка сигналов — ключевые задачи администратора и бэкенд-разработчика.

---

## Подробный теоретический минимум

### 1. Сигналы (Signals)
Сигналы — это способ межпроцессного взаимодействия для уведомления процесса о событиях:
- **`SIGINT` (Ctrl+C)**: мягкое прерывание процесса.
- **`SIGTERM` (15)**: запрос на корректное завершение работы (приложение может сохранить состояние и закрыть соединения).
- **`SIGKILL` (9)**: немедленное уничтожение процесса ядром ОС (процесс не может перехватить или проигнорировать этот сигнал).

### 2. Мониторинг и управление
- **`ps aux` / `htop`**: просмотр списка запущенных процессов и их потребления CPU/RAM.
- **`kill / pkill`**: отправка сигналов процессам.
- **`nice` / `renice`**: управление приоритетом выполнения процесса (планировщиком CPU).

---

## Производственный пример кода

Пример Bash-команды для поиска и завершения зависшего Python-процесса:

```bash
# Найти PID процесса
pgrep -f "server.py"

# Отправить сигнал SIGTERM для корректного завершения
pkill -SIGTERM -f "server.py"
```
