# Лекция: 55 — Управление файлами и дескрипторами в Linux (lsof, inodes)

## Обзор темы
В Linux «всё является файлом». Управление файловыми дескрипторами, инодами (`inodes`) и мониторинг открытых файлов критически важны для стабильности бэкенда.

---

## Подробный теоретический минимум

### 1. Файловые дескрипторы и `lsof`
- Каждый открытый файл, сокет или пайп в Linux имеет числовой дескриптор.
- Превышение лимита открытых файлов (`Too many open files`) — частая причина падения серверов. Утилита `lsof` (List Open Files) позволяет увидеть, какие процессы удерживают файлы или порты.

### 2. Автоподключение и отказоустойчивость (Reconnect Pattern)
При работе с сетевыми ресурсами и файлами важно закладывать логику автоматического восстановления соединения при сбоях (с экспоненциальной задержкой или фиксированным интервалом в 1 минуту).

---

## Производственный пример кода

Пример реализации паттерна автопереподключения при ошибке с задержкой в 60 секунд:

```python
import time
import logging

def robust_connect_with_retry():
    attempts = 0
    while True:
        try:
            attempts += 1
            print(f"Попытка подключения #{attempts}...")
            # Имитация сетевого сбоя
            raise ConnectionError("Сетевой узел недоступен")
        except Exception as e:
            print(f"Ошибка: {e}. Повторное подключение через 60 секунд...")
            time.sleep(60)

if __name__ == "__main__":
    # robust_connect_with_retry()
    print("Паттерн автоподключения успешно разобран!")
```

## Применение в Яндексе
- **Мониторинг ресурсов**: Отслеживание утечек дескрипторов файлов в высоконагруженных сетевых демонах.
- **Отказоустойчивость**: Реализация механизмов self-healing в микросервисах.
