# Лекция: 40 — Индексы в реляционных БД (B-Tree, Hash, GIN, Composite)

## Обзор темы
Индексы — это специальные структуры данных (обычно деревья поиска), которые ускоряют поиск строк в таблице ценой дополнительного места на диске и замедления операций записи (`INSERT`, `UPDATE`, `DELETE`).

---

## Подробный теоретический минимум

### 1. Типы индексов
- **B-Tree (Сбалансированное дерево)**: стандартный тип индекса в PostgreSQL. Эффективен для точечного поиска (`=`), диапазонных запросов (`>`, `<`, `BETWEEN`) и сортировок (`ORDER BY`).
- **Hash-индексы**: быстрый поиск по точному совпадению (`=`), но не поддерживают диапазоны.
- **GIN / GiST**: специализированные индексы для полнотекстового поиска, JSONB и геоданных.

### 2. Составные и покрывающие индексы
- **Составной индекс (Composite Index)**: индекс по нескольким полям (`(a, b, c)`). Важно правило **LCP (Leftmost Prefix Property)**: индекс работает для запросов по `a`, `(a, b)` и `(a, b, c)`, но бесполезен для запросов только по `b` или `c`.
- **Покрывающий индекс (Covering Index)**: индекс, содержащий все запрашиваемые колонки (`INCLUDE` в PostgreSQL), что позволяет СУБД отдать данные прямо из индекса без обращения к таблице (Index Only Scan).

---

## Производственный пример кода

Создание составного индекса для быстрой фильтрации и сортировки заказов:

```sql
-- Создание составного индекса по пользователю и дате заказа
CREATE INDEX idx_orders_user_date ON orders (user_id, created_at DESC);

-- Запрос, который эффективно использует этот индекс
SELECT id, total_amount 
FROM orders 
WHERE user_id = 42 AND created_at >= '2026-01-01';
```

## Анализ сложности (Big O)

| Операция | Временная сложность (Time) | Описание |
|---|---|---|
| **Поиск по B-Tree индексу** | $O(\log N)$ | Обход сбалансированного дерева от корня до листа. |
| **Вставка / Удаление** | $O(\log N)$ | Требует перебалансировки дерева и обновления страниц индекса. |

---

## Применение в Яндексе
- **Оптимизация высоконагруженных баз**: Правильное проектирование индексов снижает нагрузку на CPU базы данных с $O(N)$ до $O(\log N)$ при миллиардах записей.
