# Лекция: 37 — Соединения в SQL (JOIN: INNER, LEFT, RIGHT, FULL, CROSS)

## Обзор темы
Реляционные базы данных нормализуют данные по разным таблицам. Операторы `JOIN` позволяют объединять данные из связанных таблиц на основе логических условий.

---

## Подробный теоретический минимум

### 1. Виды JOIN
- **`INNER JOIN`**: возвращает только те строки, для которых есть совпадения в обеих таблицах.
- **`LEFT JOIN`**: возвращает все строки из левой таблицы и сопоставленные строки из правой (если совпадений нет, для правой таблицы подставляются `NULL`).
- **`RIGHT JOIN`**: зеркально `LEFT JOIN` (все строки из правой таблицы).
- **`FULL OUTER JOIN`**: возвращает все строки, когда есть совпадение хотя бы в одной из таблиц.
- **`CROSS JOIN`**: декартово произведение (каждая строка первой таблицы соединяется с каждой строкой второй).

### 2. Алгоритмы соединения под капотом (Join Algorithms)
СУБД использует три основных алгоритма для выполнения JOIN:
1. **Nested Loop Join**: вложенные циклы (эффективно при наличии индекса во внутренней таблице).
2. **Hash Join**: создание хэш-таблицы по ключу соединения в памяти (эффективно для больших неудаленных наборов).
3. **Merge Join**: слияние предварительно отсортированных списков.

---

## Производственный пример кода

Пример запроса для получения заказов пользователя с информацией о доставке:

```sql
SELECT 
    u.id AS user_id,
    u.username,
    o.id AS order_id,
    o.total_amount
FROM users u
INNER JOIN orders o ON u.id = o.user_id
WHERE o.status = 'completed';
```

---

## Анализ сложности (Big O)

| Алгоритм JOIN | Временная сложность (Time) | Описание |
|---|---|---|
| **Nested Loop** | $O(N \times M)$ или $O(N \log M)$ с индексом | Зависит от наличия индексов по внешнему ключу. |
| **Hash Join** | $O(N + M)$ | Построение хэш-таблицы и сканирование. |
| **Merge Join** | $O(N \log N + M \log M)$ | Требует сортировки входных данных. |
