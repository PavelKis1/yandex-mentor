# Лекция: 30 — Профилирование и анализ производительности

## Обзор темы
Профилирование позволяет находить узкие места (bottlenecks), измерять время выполнения функций и потребление памяти в Python-приложениях, предотвращая деградацию производительности под нагрузкой.

---

## Подробный теоретический минимум

### 1. Детерминированное профилирование (cProfile)
Модуль `cProfile` отслеживает все вызовы функций, возвраты и время их выполнения внутри программы.
- **Статистика**: показывает общее время (`tottime`) и кумулятивное время (`cumtime`) выполнения функций.
- **Накладные расходы**: профилирование замедляет работу программы, поэтому его используют в изолированных окружениях (staging / бенчмарки).

### 2. Измерение микро-бенчмарков (timeit)
Модуль `timeit` запускает фрагмент кода многократно (с выключением сборщика мусора на время замеров), позволяя точно сравнивать производительность разных конструкций (например, `list comprehension` против `map`).

### 3. Анализ памяти (memory_profiler)
Построчный анализ потребления оперативной памяти процесса позволяет выявить утечки памяти и избыточное создание объектов.

---

## Производственный пример кода

Использование `timeit` для сравнения производительности двух подходов к фильтрации данных:

```python
import timeit

def filter_with_comprehension(data):
    return [x for x in data if x % 2 == 0]

def filter_with_filter(data):
    return list(filter(lambda x: x % 2 == 0, data))

if __name__ == "__main__":
    sample_data = list(range(10000))
    
    t1 = timeit.timeit(lambda: filter_with_comprehension(sample_data), number=1000)
    t2 = timeit.timeit(lambda: filter_with_filter(sample_data), number=1000)
    
    print(f"List comprehension time: {t1:.4f}s")
    print(f"Filter function time: {t2:.4f}s")
    assert t1 < t2, "List comprehension should be faster due to no lambda call overhead"
    print("Бенчмарк успешно выполнен!")
```

## Анализ сложности (Big O)

| Инструмент | Временная сложность (Time) | Пространственная сложность (Space) | Описание |
|---|---|---|---|
| **cProfile** | $O(N)$ от числа вызовов | $O(K)$ | $K$ — количество уникальных функций в стеке вызовов. |
| **timeit** | $O(N \times M)$ | $O(1)$ | $N$ — число итераций, $M$ — сложность измеряемого кода. |
