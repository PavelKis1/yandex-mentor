# Лекция: 42 — Транзакции и уровни изоляции (ACID)

## Обзор темы
Транзакция — это последовательность операций, выполняемая как единое целое. Свойство **ACID** гарантирует надежность и консистентность данных в реляционных базах данных.

---

## Подробный теоретический минимум

### 1. Свойства ACID
- **Atomicity (Атомарность)**: либо выполняются все операции транзакции, либо ни одной (`COMMIT` или `ROLLBACK`).
- **Consistency (Согласованность)**: транзакция переводит БД из одного валидного состояния в другое, сохраняя все ограничения целостности (constraints).
- **Isolation (Изоляция)**: параллельные транзакции не должны влиять друг на друга.
- **Durability (Долговечность)**: после успешного подтверждения (`COMMIT`) изменения не пропадут даже при сбое питания (благодаря WAL — Write-Ahead Log).

### 2. Уровни изоляции (SQL standard)
1. **Read Uncommitted**: чтение «грязных» незакомментированных данных.
2. **Read Committed**: защита от грязного чтения (стандарт по умолчанию для PostgreSQL).
3. **Repeatable Read**: защита от грязного и неповторяющегося чтения.
4. **Serializable**: полная изоляция (эквивалентно последовательному выполнению).

## Производственный пример кода

Пример транзакции перевода средств между счетами на Python с использованием транзакционного блока:

```python
import sqlite3

def transfer_funds(conn: sqlite3.Connection, from_acc: int, to_acc: int, amount: float):
    cursor = conn.cursor()
    try:
        # Начало транзакции (в sqlite3 начинается автоматически)
        cursor.execute("UPDATE accounts SET balance = balance - ? WHERE id = ?", (amount, from_acc))
        cursor.execute("UPDATE accounts SET balance = balance + ? WHERE id = ?", (amount, to_acc))
        
        # Подтверждение транзакции
        conn.commit()
        print("Перевод выполнен успешно!")
    except Exception as e:
        # Откат при ошибке
        conn.rollback()
        print(f"Ошибка транзакции, откат: {e}")
        raise
```

## Анализ сложности (Big O)

- Транзакции добавляют накладные расходы на синхронизацию, блокировки строк (`Row-level locks`) и запись в WAL-лог.

## Применение в Яндексе
- **Финтех и Маркетплейсы**: Проведение платежей, списание средств, резервирование товаров на складе и оформление заказов без риска потерять деньги или получить несогласованные данные.
