# 📖 Лекция 03: Стеки (Stacks)

## Что это и зачем в контесте

Стек — это структура данных **LIFO** (Last In, First Out): последний вошёл — первый вышел.

**Мнемоника:** «Стек = стопка тарелок». Последнюю положил — первую берёшь. Нельзя взять из середины.

В Яндексе: проверка скобок (`()` `[]` `{}`), DFS (обход в глубину), undo/redo, вычисление выражений.

## Базовый код

```python
stack = []

# push — положить на верх
stack.append(1)      # O(1)
stack.append(2)

# pop — снять с верха
top = stack.pop()    # 2, O(1)

# peek — посмотреть верх, не снимая
top = stack[-1]      # 1, O(1)

# проверка пустоты
if not stack:
    print("Пусто")
```

## Когда использовать

- **Проверка скобок:** `(` → push, `)` → pop и сравни
- **DFS:** стек вместо рекурсии (избегаем переполнения)
- **Undo:** каждое действие — push, отмена — pop
- **Преобразование в постфикс:** `2 3 +` → стек накапливает операнды

## Сложность

| Операция | Время | Память |
|----------|-------|--------|
| Push (`append`) | O(1) | O(1) |
| Pop (`pop`) | O(1) | O(1) |
| Peek (`[-1]`) | O(1) | — |
| Перебор | O(n) | — |

## Вопросы на собеседовании в Яндексе

1. «Как проверить правильность скобок?» → стек: `(` push, `)` pop и сравни
2. «Чем стек отличается от очереди?» → стек LIFO, очередь FIFO
3. «Можно ли реализовать стек на массиве?» → Да, `list` в Python — динамический массив, `append`/`pop` в конце — O(1)
4. «Что будет, если pop из пустого стека?» → `IndexError`

## Правило ключей (повтор)

Стек не требует хешируемых ключей — это просто список элементов в порядке добавления.
