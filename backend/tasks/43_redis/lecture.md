# Лекция: 43 — Redis (In-memory хранилище данных)

## Обзор темы
Redis — это высокопроизводительное хранилище данных типа «ключ-значение», работающее в оперативной памяти (`In-memory`). Оно используется как кэш, брокер сообщений и распределенный кэш в высоконагруженных системах.

---

## Подробный теоретический минимум

### 1. Основные структуры данных
- **String**: строки, числа (поддерживаются атомарные инкременты/декременты).
- **Hash**: хэш-таблицы внутри ключа (удобно для хранения объектов, например профилей пользователей).
- **List / Set / Sorted Set (ZSet)**: списки, множества и отсортированные множества (идеально для рейтингов и лидербордов).

### 2. Время жизни ключей (TTL) и персистентность
- **TTL (Time To Live)**: установка времени жизни ключа для автоматического удаления (ключевой механизм для кэширования).
- **Персистентность**: RDB (снимок памяти на диск) и AOF (логирование каждой операции записи).

---

## Производственный пример кода

Пример использования Redis на Python с библиотекой `redis-py` для реализации кэширования:

```python
import redis

# Подключение к Redis
r = redis.Redis(host='localhost', port=6379, decode_responses=True)

def get_user_cached(user_id: int) -> str:
    cache_key = f"user:{user_id}"
    
    # 1. Проверяем кэш
    cached_name = r.get(cache_key)
    if cached_name:
        return f"From Cache: {cached_name}"
    
    # 2. Имитация запроса в БД
    user_name = f"User_{user_id}"
    
    # 3. Сохраняем в кэш с TTL 60 секунд
    r.setex(cache_key, 60, user_name)
    return f"From DB: {user_name}"

if __name__ == "__main__":
    print(get_user_cached(1))
    print(get_user_cached(1))  ггг
```

## Анализ сложности (Big O)

| Операция | Временная сложность (Time) | Описание |
|---|---|---|
| **GET / SET** | $O(1)$ | Мгновенный доступ к данным в оперативной памяти. |
| **ZADD / ZRANGE** | $O(\log N)$ | Операции с отсортированными множествами на базе skip-list. |

---

## Применение в Яндексе
- **Кэширование**: Снижение нагрузки на реляционные базы данных.
- **Rate Limiting**: Ограничение частоты запросов от пользователей (защита от DDoS и спама).
- **Распределенные блокировки**: Синхронизация задач в кластере через Redlock.
