# Лекция: 41 — Анализ планов запросов (EXPLAIN / EXPLAIN ANALYZE)

## Обзор темы
Команда `EXPLAIN` показывает план выполнения SQL-запроса оптимизатором СУБД. Это главный инструмент разработчика для отладки производительности и поиска неоптимальных запросов.

---

## Подробный теоретический минимум

### 1. Как читать план запроса
- **Seq Scan (Sequential Scan)**: полный перебор всех строк таблицы. На больших таблицах приводит к деградации производительности.
- **Index Scan / Index Only Scan**: поиск по индексу. `Index Only Scan` быстрее, так как данные берутся прямо из индекса.
- **Cost (Стоимость)**: условные единицы стоимости выполнения запроса (например, `cost=0.00..35.50`). Первая цифра — стоимость старта, вторая — общая стоимость.
- **Rows**: оценочное количество строк, которое вернет узел.

### 2. EXPLAIN ANALYZE
В отличие от простого `EXPLAIN`, модификатор `ANALYZE` **реально выполняет запрос** в базе данных и выводит реальное время выполнения, количество итераций (`loops`) и реальное число обработанных строк.

---

## Производственный пример кода

Пример анализа запроса в PostgreSQL:

```sql
-- Анализ реального времени выполнения и использования индексов
EXPLAIN ANALYZE
SELECT id, username 
FROM users 
WHERE email = 'user@yandex.ru';
```

---

## Анализ сложности (Big O)

- Цель оптимизации с помощью `EXPLAIN` — перевести выполнение запроса из линейной сложности $O(N)$ (Seq Scan) в логарифмическую $O(\log N)$ (Index Scan).

---

## Применение в Яндексе
- **Troubleshooting**: Расследование инцидентов деградации базы данных при резком росте нагрузки (высокий CPU / долгие запросы).
- **Code Review**: Проверка новых SQL-миграций и запросов от ORM перед релизом на продакшн.
