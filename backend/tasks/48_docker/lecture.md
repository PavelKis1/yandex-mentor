# Лекция: 48 — Контейнеризация с Docker (Dockerfile, образы, слои)

## Обзор темы
Docker — технология контейнеризации, позволяющая упаковать приложение со всеми его зависимостями, библиотеками и конфигурациями в изолированный контейнер, который гарантированно работает на любом сервере.

---

## Подробный теоретический минимум

### 1. Архитектура и Dockerfile
- **Образ (Image)**: неизменяемый шаблон, состоящий из слоев (layers), содержащий ОС, код и зависимости.
- **Контейнер (Container)**: запущенный экземпляр Docker-образа.
- **Dockerfile**: текстовый файл с инструкциями по сборке образа (`FROM`, `WORKDIR`, `COPY`, `RUN`, `CMD`).

### 2. Кэширование слоев
Каждая инструкция в `Dockerfile` создает новый слой. Docker кэширует слои при сборке: если файл не изменился, слой берется из кэша, что ускоряет сборку.
- **Best Practice**: копировать файлы зависимостей (`requirements.txt`, `pyproject.toml`) и устанавливать их **до** копирования исходного кода приложения, чтобы кэш зависимостей не инвалидировался при каждом изменении кода.

---

## Производственный пример кода

Пример production-ready `Dockerfile` для FastAPI приложения:

```dockerfile
# Используем официальный легковесный образ Python
FROM python:3.11-slim

# Установка рабочей директории
WORKDIR /app

# Установка зависимостей (используем кэширование слоев)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Копирование исходного кода
COPY . .

# Команда запуска приложения
CMD ["uvicorn", "server:app", "--host", "0.0.0.0", "--port", "8000"]
```

## Анализ сложности (Big O)

- Контейнеризация имеет нулевые накладные расходы на производительность CPU по сравнению с «железом», так как процессы работают в изоляции на ядре хоста.

## Применение в Яндексе
- **Деплой и оркестрация**: Все бэкенд-сервисы упаковываются в Docker-образы и деплоятся в облачные кластеры (например, Yandex Cloud / Kubernetes).
