# Лекция: 29 — Внутренности Python (CPython Internals)

## Обзор темы
Понимание внутреннего устройства CPython (официальной и самой популярной реализации Python) необходимо для написания высокопроизводительного, потокобезопасного и эффективного по памяти бэкенд-кода.

---

## Подробный теоретический минимум

### 1. GIL (Global Interpreter Lock)
GIL — это мьютекс, который гарантирует, что в каждый момент времени только один поток исполняет байткод Python.
- **Влияние на многопоточность (`threading`)**: потоки не могут параллельно выполнять вычисления на нескольких ядрах процессора (CPU-bound задачи).
- **Когда GIL не мешает**: в задачах, ожидающих ввода-вывода (I/O-bound: запросы к БД, сети, диску), GIL освобождается во время системных вызовов (`socket.recv()`, `time.sleep()`).

### 2. Управление памятью и сборка мусора (GC)
- **Подсчет ссылок (Reference Counting)**: каждый объект содержит счетчик `ob_refcnt`. Когда счетчик падает до нуля, память освобождается немедленно.
- **Поколенческий сборщик мусора (Generational GC)**: решает проблему циклических ссылок (`A` ссылается на `B`, а `B` на `A`). Делит объекты на 3 поколения и периодически сканирует их.
- **pymalloc**: специализированный аллокатор памяти для небольших объектов (до 512 байт), снижающий накладные расходы на системные вызовы `malloc`/`free`.

### 3. Байткод и виртуальная машина
Исходный код `.py` компилируется в промежуточный байткод (`.pyc`), который выполняется стековой виртуальной машиной CPython. Инструкции байткода можно исследовать с помощью модуля `dis`.

---

## Производственный пример кода

Пример анализа байткода функции с помощью встроенного модуля `dis`:

```python
import dis

def calculate_total(a: int, b: int) -> int:
    return a + b * 2

if __name__ == "__main__":
    print("--- Байткод функции calculate_total ---")
    dis.dis(calculate_total)
```

## Анализ сложности (Big O)

| Операция / Механизм | Временная сложность (Time) | Пространственная сложность (Space) | Описание |
|---|---|---|---|
| **Подсчет ссылок** | $O(1)$ | $O(1)$ | Изменение счетчика при создании/удалении ссылок. |
| **Сборщик мусора (GC cycle)** | $O(N)$ | $O(N)$ | Проход по объектам поколения в поисках циклов. |

## Применение в Яндексе
- **Проектирование архитектуры**: Выбор между `asyncio` (для I/O-bound микросервисов) и `multiprocessing` / `Celery` (для тяжелых CPU-bound задач машинного обучения и обработки данных).
- **Оптимизация RAM**: Предотвращение утечек памяти из-за циклических ссылок в долгоживущих воркерах.
