# Лекция: 45 — REST API (Representational State Transfer)

## Обзор темы
REST — это архитектурный стиль взаимодействия компонентов распределенного приложения через протокол HTTP, использующий стандартные методы и концепцию ресурсов.

---

## Подробный теоретический минимум

### 1. Основные принципы REST
1. **Клиент-серверная архитектура**: разделение интерфейса и логики хранения данных.
2. **Отсутствие состояния (Stateless)**: каждый запрос от клиента должен содержать всю информацию, необходимую для его обработки (сервер не хранит контекст сессии между запросами).
3. **Кэшируемость**: ответы сервера должны явно указывать, можно ли их кэшировать.
4. **Единообразие интерфейса (Uniform Interface)**:
   - Использование существительных во множественном числе для именования ресурсов (`/users`, `/orders`).
   - Использование стандартных HTTP-методов для манипуляций с ресурсами.

### 2. Проектирование эндпоинтов
- `GET /users` — получить список пользователей.
- `POST /users` — создать нового пользователя.
- `GET /users/{id}` — получить пользователя по ID.
- `PUT /users/{id}` — обновить пользователя целиком.
- `DELETE /users/{id}` — удалить пользователя.

## Производственный пример кода

Пример проектирования REST-эндпоинтов с использованием FastAPI:

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from typing import List

app = FastAPI()

class Item(BaseModel):
    name: str
    price: float

items_db = []

@app.get("/items", response_model=List[Item])
def get_items():
    return items_db

@app.post("/items", status_code=201)
def create_item(item: Item):
    items_db.append(item)
    return item
```
