# 📖 Лекция 01: Хеш-таблицы (Hash Tables)

## 📝 О чем это
Хеш-таблица — это одна из важнейших структур данных в информатике. Она позволяет хранить пары «ключ-значение» и обеспечивает крайне быстрый доступ к данным (в среднем O(1)). Именно благодаря хеш-таблицам работают словари (`dict`) и множества (`set`) в Python, индексация в базах данных и механизмы кэширования. Понимание их внутреннего устройства — ключ к написанию эффективного кода, который проходит по ограничениям времени в задачах Яндекса.

## 💡 Основные концепции
Хеш-таблица базируется на **хеш-функции**. Это алгоритм, который преобразует произвольный ключ (строку, число, кортеж) в целое число — **хеш**. Этот хеш затем используется для определения индекса в массиве (корзине), где будет храниться значение.

### Ключевые моменты:
1.  **Хеш-функция**: Должна быть детерминированной (для одного и того же ключа всегда возвращать один и тот же хеш) и быстро вычисляемой.
2.  **Коллизии**: Ситуация, когда хеш-функция возвращает одинаковый индекс для двух разных ключей. Даже при идеальной хеш-функции коллизии неизбежны (принцип Дирихле).
3.  **Разрешение коллизий**:
    *   **Метод цепочек (Chaining)**: В каждой ячейке массива хранится список (или другая структура) элементов, имеющих одинаковый хеш.
    *   **Открытая адресация (Open Addressing)**: При коллизии алгоритм ищет следующую свободную ячейку по определенному правилу (линейное пробирование, квадратичное пробирование и т.д.). **Python использует вариацию открытой адресации**.
4.  **Коэффициент загрузки (Load Factor)**: Отношение количества элементов к размеру массива. Когда он превышает определенный порог (например, 0.75), таблица увеличивается в размере, и происходит **рехеширование** (пересчет хешей всех элементов для новых индексов). Это дорогая операция.

## 🛠 Популярные методы
### dict:
*   `d.get(k, default=None)`: Безопасное получение. Возвращает значение, если ключ есть, иначе — `default`. Использование `get` вместо `d[k]` предотвращает `KeyError`.
*   `d.setdefault(k, default)`: Получает значение, а если ключа нет, устанавливает `default` и возвращает его. Очень удобно для инициализации списков внутри словарей.
*   `d.keys()`, `d.values()`, `d.items()`: Возвращают представления (views), которые динамически обновляются при изменении словаря.
*   `d.update(other)`: Быстрое слияние другого словаря в текущий.
*   `d.pop(k, default)`: Удаляет ключ и возвращает его значение.

### set:
*   `s.add(x)`, `s.discard(x)`: Добавление и безопасное удаление (не вызывает ошибку, если элемента нет, в отличие от `remove`).
*   `s.union(other)`, `s.intersection(other)`, `s.difference(other)`: Методы для теоретико-множественных операций, работающие очень быстро.

## 💻 Базовый код и примеры
```python
# Инициализация и доступ
data = {"a": 1, "b": 2}
val = data.get("c", 0)  # Безопасно, вернет 0, а не KeyError

# Использование set для дедупликации
arr = [1, 2, 2, 3, 3, 3]
unique_elements = list(set(arr)) # O(n)

# Группировка элементов (частая задача)
from collections import defaultdict
groups = defaultdict(list)
for i in range(10):
    groups[i % 2].append(i) # Группировка по четности
```

## 🚀 Сложность (Time/Space Complexity)
| Операция | Среднее | Худшее |
|---|---|---|
| Поиск | O(1) | O(n) |
| Вставка | O(1) | O(n) |
| Удаление | O(1) | O(n) |

*Примечание: Худшее время O(n) достигается при возникновении «кластеров» коллизий или при переполнении таблицы и необходимости рехеширования.*

## 💡 Тонкости и "подводные камни"
1.  **Изменяемые ключи**: Хеш-таблица полагается на то, что хеш ключа не изменится. Если вы сделаете `list` ключом, а потом измените список, `dict` «сломается» (не найдет ключ). Поэтому **только неизменяемые типы** (tuple, int, str) могут быть ключами.
2.  **Рехеширование**: Добавление большого количества элементов может внезапно замедлить программу из-за необходимости перестроения таблицы.
3.  **Потребление памяти**: Хеш-таблицы всегда требуют больше памяти, чем хранят элементов, чтобы минимизировать коллизии.
