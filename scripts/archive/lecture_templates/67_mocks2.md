# 📖 Лекция 67: Работа с unittest.mock

## 📝 О чем это
Библиотека `unittest.mock` — это стандартный инструмент в Python для создания моков. Она глубоко интегрирована в экосистему и позволяет гибко подменять объекты, методы и даже целые модули.

## 💡 Основные концепции
1.  **MagicMock**: Самый популярный тип мока. Он поддерживает все «магические» методы (например, `__iter__`, `__enter__`), что позволяет мокать сложные объекты (файлы, контекстные менеджеры).
2.  **patch**: Декоратор или контекстный менеджер, который заменяет объект в пространстве имен на время теста.
3.  **autospec**: Полезный параметр `patch`, который автоматически создает мок с интерфейсом реального объекта, предотвращая вызов несуществующих методов.

## 🛠 Популярные методы
*   `mock.assert_called()`: Проверка, что метод был вызван.
*   `mock.assert_called_with(...)`: Проверка аргументов вызова.
*   `mock.call_count`: Счетчик вызовов.

## 💻 Базовый код и примеры
```python
from unittest.mock import patch, MagicMock

# Использование patch как декоратора
@patch('my_module.external_api')
def test_something(mock_api):
    mock_api.return_value = 'mocked response'
    result = my_function_using_api()
    assert result == 'mocked response'
    mock_api.assert_called_once()
```

## 🚀 Сложность
*   Использование `unittest.mock` практически не влияет на скорость выполнения тестов (O(1)).

## 💡 Тонкости
*   Используйте `autospec=True`, чтобы не мокать методы, которых нет в реальном объекте. Это сэкономит часы отладки при рефакторинге.
