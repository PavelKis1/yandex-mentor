# 📖 Лекция 66: Основы тестирования с моками (Mocks)

## 📝 О чем это
Мокирование — это техника в модульном тестировании, которая позволяет подменять зависимости вашего кода (внешние API, БД, другие модули) «заглушками», которые ведут себя предсказуемо. Это позволяет тестировать изолированный код, не завися от состояния внешней среды, что критически важно для быстрых и детерминированных тестов.

## 💡 Основные концепции
1.  **Test Double**: Общий термин для объектов, заменяющих реальные зависимости (Dummy, Stub, Spy, Mock).
2.  **Stub (Заглушка)**: Просто возвращает заранее заданные значения. Не проверяет, как она была вызвана.
3.  **Mock (Мок)**: Проверяет взаимодействие: был ли вызван метод, сколько раз, с какими аргументами.
4.  **Spy (Шпион)**: Оборачивает реальный объект, записывая все взаимодействия, но позволяя методам работать как обычно.

## 🛠 Популярные методы
*   `patch()`: Подмена объекта в указанном модуле на время выполнения теста.
*   `return_value`: Указание значения, которое вернет мок при вызове.
*   `side_effect`: Указание функции или исключения, которое будет вызвано при вызове мока.

## 💻 Базовый код и примеры
```python
from unittest.mock import Mock

# Простая заглушка
mock_db = Mock()
mock_db.get_user.return_value = {"id": 1, "name": "Alice"}

# Проверка вызова
mock_db.get_user(1)
mock_db.get_user.assert_called_once_with(1)
```

## 🚀 Сложность (Time/Space Complexity)
*   **Time**: Тесты с моками работают быстрее, так как не делают реальных сетевых/дисковых вызовов (O(1) вместо O(N)).
*   **Space**: Потребление памяти минимально, но моки могут создавать дополнительные объекты в памяти в процессе теста.

## 💡 Тонкости и "подводные камни"
1.  **Чрезмерное мокирование**: Если вы замокали почти всё, тест может перестать проверять реальную логику работы системы.
2.  **Хрупкие тесты**: Если вы слишком детально мокаете внутреннюю реализацию (private методы), любой рефакторинг сломает тесты, даже если логика верна.
